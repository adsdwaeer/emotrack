# ЭмоТрек — оценка вовлечённости слушателей онлайн-занятий

Прототип программного приложения по дисциплине «Проектный практикум 3».
Продолжение прототипа с 1 курса (веб-сервис распознавания эмоций на фото, Flask + FastAPI,
модель `dima806/facial_emotions_image_detection`): теперь сервис анализирует **видео занятия**
и считает **индекс вовлечённости** каждого слушателя и занятия в целом.

**Автор:** Кузнецов Никита, гр. 4.506М-3, АлтГУ, 2026
**Основание:** техническое задание на АС «ЭмоТрек» (ГОСТ 34.602-2020), разделы 4.1–4.3.
Прототип реализует ядро требований ТЗ в упрощённом виде (см. «Ограничения»).

---

## Что умеет

- принимает **видеозапись занятия** (запись вебинара) и обрабатывает её в фоне;
- **живой режим**: кадры с веб-камеры раз в 2 с отправляются на сервер, индекс обновляется на лету;
- выбирает 1 кадр в 2 с → находит лица (YuNet) → проверяет качество (размер, освещённость,
  резкость, поворот головы) → сопровождает лица между кадрами и присваивает ID участникам
  (P1, P2, …) → классифицирует 7 эмоций моделью ViT батчами → агрегирует в 30-секундные интервалы;
- считает **индекс вовлечённости** по формуле ТЗ (п. 4.2) — для интервала, слушателя и занятия
  (по минутам), выставляет флаг **«зона риска»** (индекс < 40) и цветовой уровень;
- хранит в SQLite **только агрегаты** (вероятности эмоций и индексы); видео удаляется сразу после
  обработки, кадры и лица на диск не пишутся (152-ФЗ, ТЗ п. 4.1.8);
- **дашборд** преподавателя/куратора: список занятий, график индекса по минутам, индекс участников
  по интервалам, таблица участников с цветовой индикацией и флагом риска, распределение эмоций,
  экспорт CSV;
- **REST API** (FastAPI, Swagger на `/docs`);
- риск отчисления по ТЗ: слушатель с индексом < 40 на **трёх занятиях подряд**
  (после привязки участника к идентификатору слушателя LMS).

## Установка

```bash
pip install -r requirements.txt

# веса YuNet (230 КБ) и тестовая часть FER-2013; --train — ещё обучающая часть (для демо-видео)
python scripts/download_data.py --train

# только для скриншотов
playwright install chromium
```

Модель ViT (~330 МБ) скачивается с Hugging Face автоматически при первом запуске.

## Архитектура

```
 видеофайл ─┐                       emotrack/pipeline.py
 веб-камера ┴─► выборка кадров ─► детекция лиц ─► качество ─► трекер ─► ViT (батчи)
              (1 кадр / 2 с)      detector.py      detector.py  tracker.py  classifier.py
                                                                              │
         SQLite (только агрегаты) ◄── агрегация 30 с + индекс ◄────────────────┘
              storage.py               aggregation.py, engagement.py
                  │
          FastAPI (api.py) ──► REST API /api/...  +  дашборд (templates/, static/)
```

| Файл | Назначение |
|---|---|
| `emotrack/config.py` | все настройки: шаг кадров, интервал, пороги качества, **веса индекса** |
| `emotrack/detector.py` | YuNet / Haar, вырезка лица, проверка качества и поворота головы |
| `emotrack/classifier.py` | ViT: препроцессинг (OpenCV), батчи, fp16 на GPU |
| `emotrack/tracker.py` | сопровождение лиц по IoU и расстоянию между центрами |
| `emotrack/aggregation.py` | 30-секундные интервалы, q, отсев ложных срабатываний |
| `emotrack/engagement.py` | формула индекса, уровни, зона риска, динамика по минутам, риск отчисления |
| `emotrack/pipeline.py` | конвейер: `LessonAnalyzer` (видео и живой режим), `analyze_video` |
| `emotrack/storage.py` | SQLite: занятия, участники, интервалы |
| `emotrack/api.py` | REST API и страницы дашборда |
| `evaluation/` | оценка качества на FER-2013, сравнение детекторов, результаты |
| `scripts/` | загрузка данных, демо-видео, прогон демо, бенчмарк, скриншоты |
| `tests/` | pytest (классификатор и детектор подменяются заглушками) |

**Почему YuNet, а не Haar.** На плитках «вебинара» из 500 изображений FER-2013
(`evaluation/detector_comparison.py`) YuNet находит лицо в 94,6 / 97,0 / 97,8 % случаев
(лицо 120 / 170 / 220 px), Haar — в 77,2 / 77,6 / 76,4 %; YuNet быстрее (≈2,0 мс против 5,5–6,4 мс
на плитку) и даёт 5 ключевых точек, по которым оценивается поворот головы — это нужно для q
(«лицо обнаружено и направлено на экран»). Веса — 230 КБ, лицензия MIT, контрольная сумма
проверяется при загрузке. Без файла весов автоматически включается Haar.

## Индекс вовлечённости

Формула ТЗ, п. 4.2:

```
E = 100 · (w1·p(радость) + w2·p(удивление) + w3·p(нейтрально) − w4·p(грусть) − w5·p(злость) + c) · q
```

- `p(·)` — средняя вероятность эмоции по кадрам интервала, где лицо найдено и прошло проверку качества;
- `q` — доля выбранных кадров интервала, где лицо обнаружено и направлено на экран;
- результат обрезается в [0, 100].

| Вес | Эмоция | Значение по умолчанию |
|---|---|---|
| w1 | радость | 0,70 |
| w2 | удивление | 0,60 |
| w3 | нейтрально | 0,50 |
| w4 | грусть (−) | 0,50 |
| w5 | злость (−) | 0,40 |
| c | свободный член | 0,25 |

Логика: внимательный слушатель чаще всего выглядит нейтрально, поэтому «чистая» нейтральность даёт
75 (зелёная зона), чистая радость — 95, чистая грусть — 0; страх и отвращение в формулу ТЗ не входят
(дают только c = 25). Веса заданы экспертно в `config.py`; **их калибровка по экспертной разметке
кураторов (линейная регрессия с ограничениями на знаки) — задача ВКР** (этап 3 ТЗ).

- индекс слушателя за занятие — среднее его 30-секундных интервалов, начиная с момента появления
  (интервалы без лица входят нулём — отсутствие у экрана снижает индекс);
- индекс занятия по минутам — среднее индексов всех участников в интервалах этой минуты;
  индекс занятия — среднее индексов слушателей;
- уровни: **≥ 70 зелёный**, **40–69 жёлтый**, **< 40 красный**; **зона риска** — индекс < 40;
- риск отчисления — индекс < 40 на трёх последних занятиях подряд (`GET /api/students/at-risk`).

## Оценка качества модели (FER-2013)

Набор: FER-2013, тестовая часть **PrivateTest** (3589 изображений 48×48), с Hugging Face Hub
(`Aaryan333/fer2013_train_publicTest_privateTest`, parquet). Основная оценка —
**стратифицированная выборка 2000 изображений** (seed 42), классификатор тот же, что в конвейере.
Файлы: `evaluation/results/metrics.json`, `per_class_privateTest.csv`,
`confusion_matrix_privateTest.png`, `confusion_matrix_training.png`.

| Выборка | n | Accuracy | Macro-F1 | Weighted-F1 |
|---|---|---|---|---|
| PrivateTest, стратифицированная выборка | 2000 | **0,8775** | **0,8822** | 0,8774 |
| PrivateTest целиком | 3589 | 0,8830 | 0,8863 | 0,8828 |
| Training (контроль утечки), выборка | 2000 | 0,8790 | 0,8833 | 0,8788 |

По классам (PrivateTest, n = 2000):

| Эмоция | Precision | Recall | F1 | n |
|---|---|---|---|---|
| Злость | 0,850 | 0,872 | 0,861 | 273 |
| Отвращение | 0,886 | 1,000 | 0,939 | 31 |
| Страх | 0,862 | 0,806 | 0,833 | 294 |
| Радость | 0,958 | 0,939 | 0,949 | 490 |
| Нейтрально | 0,842 | 0,854 | 0,848 | 349 |
| Грусть | 0,805 | 0,813 | 0,809 | 331 |
| Удивление | 0,917 | 0,957 | 0,937 | 232 |

Основные ошибки — путаница грусть ↔ нейтрально ↔ злость ↔ страх (см. матрицу ошибок).

**Важно: эти цифры завышены и не являются оценкой обобщающей способности.**
По Kaggle-ноутбуку автора модели (`dima806/facial-emotions-image-detection-vit`, текущая версия)
она обучалась на наборе `samaneheslamifar/facial-emotion-expressions` — судя по описанию
(48×48, оттенки серого, те же 7 классов), это производный от FER-2013 набор. В обучение брались
**все** папки набора, а разбиение 60/40 на train/test делалось уже после случайного дублирования
(oversampling) редких классов — поэтому и заявленные в карточке модели 91 % завышены. Тестовые
изображения FER-2013, по всей видимости, были в обучении модели. Это подтверждает эксперимент: точность на обучающей части
(0,879) совпадает с точностью на тестовой (0,8775), а лучшие опубликованные результаты на FER-2013
— около 73–76 %. Дополнительно найдено 288 из 3589 изображений PrivateTest, которые побайтно
совпадают с изображениями Training. Честная проверка требования ТЗ (accuracy ≥ 70 %,
macro-F1 ≥ 0,60 «на тестовой выборке Заказчика») возможна только на собственных размеченных
кадрах — это задача ВКР.

## Демонстрация на видео

Видео «вебинара» (`scripts/make_demo_video.py`): сетка 3×2 из шести «слушателей», 8 минут,
1280×720, 25 к/с. Лица — изображения **открытого набора FER-2013** (обучающая часть), каждые 4 с
меняются по заранее заданному сценарию (сценарии и «истинные» эмоции сохраняются в JSON).
Изображения реальных людей из интернета вне открытого датасета не используются.

Результат (`scripts/run_demo.py`, `docs/demo_results.json`), индекс занятия **55,3 (жёлтый)**:

| Слушатель (сценарий) | ID | Индекс | Ожидаемый по сценарию | Уровень | Лицо в кадре |
|---|---|---|---|---|---|
| 1 — активный: радость, удивление | P2 | 72,4 | 86,3 | зелёный | 95 % |
| 2 — спокойный, в основном нейтрально | P5 | 54,4 | 63,2 | жёлтый | 94 % |
| 3 — **теряет интерес**: нейтр./радость → грусть → уходит | P3 | **36,5** | 40,4 | красный, **зона риска** | 85 % |
| 4 — отходит от камеры на 2–4-й мин | P1 | 46,9 | 59,9 | жёлтый | 67 % |
| 5 — раздражение на 3–5,5-й мин | P4 | 49,0 | 55,2 | жёлтый | 96 % |
| 6 — подключился через 1,5 мин | P6 | 72,6 | 84,5 | зелёный | 98 % |

- «Слушатель 3» первые 2,5 мин держится в зелёной зоне (79–85), с 2:30 уходит в красную
  (24, 20, 49, 38, 25, 17, 11, затем 0 — ушёл от камеры) и получает **флаг риска** — единственный
  из шести.
- У «слушателя 4» интервалы 2:00–4:00 равны 0 (q = 0), у «слушателя 5» на 3:00–5:30 индекс падает
  до 0–25 (злость), но по занятию в целом оба остаются в жёлтой зоне.
- «Слушатель 6» не штрафуется за время до подключения: его интервалы начинаются с 1:30.
- Индекс занятия по минутам: 68,7 → 63,9 → 53,8 → **42,7** → 52,3 → 51,3 → 51,9 → 56,6 —
  провал на 4-й минуте, когда одновременно грустит слушатель 3, отсутствует слушатель 4 и злится
  слушатель 5.
- Сравнение с «ожидаемым» индексом (та же формула по истинным эмоциям сценария) по 93 интервалам:
  **корреляция Пирсона r = 0,930, MAE = 11,3** пункта. Измеренный индекс систематически ниже
  ожидаемого: модель часть нейтральных лиц относит к грусти/страху, а 58 из 1297 найденных лиц
  (4,5 %) отбракованы проверкой качества (в FER-2013 много лиц в пол-оборота).

## Производительность

Демо-видео 8:00 (240 выбранных кадров, 1239 классифицированных лиц), AMD Ryzen 7 7700
(PyTorch: 4 потока), NVIDIA GeForce RTX 5060 Ti, torch 2.12.0+cu130 (`docs/benchmark.json`):

| | GPU (fp16) | CPU (fp32) |
|---|---|---|
| Полное время обработки | 8,4 с | 160,8 с |
| Выбранных кадров в секунду | 28,6 | 1,49 |
| Лиц в секунду (классификация) | 428,9 | 8,0 |
| Время обработки 1 минуты видео | **1,05 с** | **20,1 с** |
| Быстрее реального времени | в 57 раз | в 3 раза |
| Детекция YuNet / классификация / чтение видео | 3,3 / 2,9 / 2,2 с | 3,6 / 155,0 / 2,2 с |

Перевод препроцессинга с PIL на OpenCV/NumPy и fp16 на GPU ускорили классификацию в ~2,2 раза
(с 192,5 до 428,9 лиц/с); совпадение предсказаний с эталонным PIL-препроцессором — 99,4 %,
метрики на FER-2013 практически не изменились. Для живого режима нужен 1 кадр в 2 с на
занятие — с запасом выполняется и на CPU при небольшой группе.

## Ограничения

- **Качество модели на реальных данных неизвестно**: метрики на FER-2013 завышены из-за
  пересечения с обучающими данными модели (см. выше). Модель обучена на чёрно-белых 48×48 снимках,
  поэтому кадры с камеры переводятся в оттенки серого; на живых веб-камерах точность будет ниже.
- **Веса индекса экспертные**, не откалиброваны по оценкам кураторов; корреляция индекса с
  экспертной оценкой (≥ 0,6 по ТЗ) не проверялась — нужна разметка.
- Демо-видео синтетическое: у «слушателя» каждые 4 с меняется внешность (в FER-2013 нет ID людей),
  а изображения из обучающей выборки модели распознаются лучше, чем реальные лица.
- Трекер простой (IoU + центры): рассчитан на неподвижные плитки вебинара; при перестановке
  плиток или смене раскладки ID участников могут перепутаться. ID не переиспользуются: если
  короткое ложное срабатывание отброшено, в нумерации остаётся пропуск (например, P7 без P6).
- Связь «лицо ↔ слушатель LMS» не автоматическая (в ТЗ — интеграция с платформой вебинаров),
  в прототипе привязка делается вручную через `PUT /api/participants/{id}`.
- Оценка поворота головы — грубая (по положению носа относительно глаз), наклон головы и
  направление взгляда не учитываются.
- Не реализованы из ТЗ: разграничение доступа по ролям, HTTPS, журналирование действий,
  учёт согласий, уведомления кураторов, PostgreSQL/Redis/Docker, React. Хранилище — SQLite,
  фоновая обработка — `BackgroundTasks` в одном процессе (видео обрабатываются по очереди).
- Проверка смещения модели по полу и возрасту (ТЗ п. 4.1.12) не выполнена: в FER-2013 нет таких меток.
- Ограничение размера загружаемого видео не задано.
